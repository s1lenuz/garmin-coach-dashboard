1核心结论

这半年接口政策变化很大，很多教程已经过时。

2026-10-21，Garmin 重新开放 Connect Developer Program，并首次把个人用户单列为 Personal 层级：个人免费、无需审批、几秒钟自助生成 API Key，可读自己的活动与健康数据。此前（2026-03 起）该项目因 AI 生成应用申请暴增冻结了 7 个月，而且旧体系把所有人当企业审核，个人基本申请不下来。
所以本项目走官方 Personal API，不用 python-garminconnect / garth 这类模拟网页登录的非官方方案，也不碰私有接口。

3认证链路与关键约束

Key 与 token
Key 有效期 30 / 90 / 180 / 365 天，只显示一次，可随时撤销；token 24 小时有效且无 refresh token，过期用同一个 Key 重新换即可。代码解析 JWT 的 exp 并按 23 小时保守缓存，遇 401 自动重换重试一次。
中国区主机
全球区 personal.connectapi.garmin.com；中国区账号实测走 personal.connectapi.garmin.cn。本项目用 GARMIN_REGION=cn|global 自动切换，也支持显式覆盖。单一账户实测通过不代表所有中国区账户均可用，需自行做最小只读验证。
被剥离的专有指标
经 API 下发的 .FIT 会移除 VO2 max、恢复时间、训练效果、乳酸阈值等未文档化字段（手动从 Connect 下载原始 .FIT 仍有）。睡眠、心率、HRV、卡路里不受影响。
字段不保证一致
不同设备 / 地区 / 账户返回的字段可能不同。本项目做多候选映射、找不到就留 null，并把原始 JSON 完整留存到 data/raw/，看板里可一键查看核对，绝不猜字段含义或把缺失补成 0。

4看板架构

  • 零依赖：只用 Python 3.9+ 标准库与浏览器原生能力，不需要 pip install、不加载任何 CDN。
  • 缓存分层：Garmin 数据按 TTL 缓存，原始 JSON 全量留存；DeepSeek 解读按统计内容哈希缓存，重复刷新不重复计费。
  • 降级链：范围端点失败 → 逐日端点；Garmin 不可用 → 上次缓存 → 演示数据；DeepSeek 不可用 → 基于真实统计的规则解读。每一级都在界面上明确标注，不静默伪造。
  • 隐私：只把聚合统计（周均值、环比、异常日、相关系数）发给大模型，不发送逐日明细、账户标识或任何密钥。

7你只需要做 3 件事

  1. 在项目根目录把 .env.example 复制为 .env（这个文件不会进 Git）。
  2. 登录 Garmin Connect 网页版 → 设置 → Personal API Key → Create Key，选有效期（建议 1 年），立刻复制；填到 GARMIN_PERSONAL_API_KEY。中国区账号加一行 GARMIN_REGION=cn。
  3. 把 DeepSeek 的 Key 填到 DEEPSEEK_API_KEY，运行 python server.py，打开 http://127.0.0.1:8765。用右上角「测试连接」验证即可。
不想现在配置也行：不填任何 Key 时，看板自动用内置 90 天演示数据完整运行；直接双击 web/index.html 也能离线查看（已预生成 7/14/30/90 天四套数据）。
